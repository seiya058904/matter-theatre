# Matter Theatre 性能审计

基线为 `940b97c`，使用相同的 63 个模板、五种画风和种子 7 对比优化版。测试环境为 Windows、Ryzen 7 9700X、Radeon RX 7900 XT、Chromium 156.0.8078.4 硬件 WebGL 2、Node 22.23.5、Matter.js 0.20.0 和 PixiJS 8.23.0。浏览器使用 Vite 生产构建。

## 瓶颈与改动

- 密集场景的浏览器 CPU 采样集中在 SAT 多边形投影、碰撞支持点和接触求解。物理步进在同一次检测中复用多边形沿自身轴的投影，保留 Matter.js 的扫掠顺序、接触点、求解迭代、120 Hz 固定步长和场景种子。预稳定只在最后一步写入供首帧插值使用的位姿快照。[Matter.js 检测器](https://brm.io/matter-js/docs/files/src_collision_Detector.js.html)、[Matter.js Engine](https://brm.io/matter-js/docs/classes/Engine.html)
- Pixi 采样显示顶点打包和动态路径构建是主要 CPU 渲染成本。软体多层填充复用 Pixi 的二次曲线细分结果，轨迹用环形历史并按变化上传，切走场景时释放轨迹几何和缓冲区。静止背景只在着色器输入变化时重绘，墨晕和光圈转场持续复用已挂载的滤镜和遮罩。[PixiJS Graphics](https://pixijs.com/8.x/guides/components/scene-objects/graphics)、[PixiJS 性能指南](https://pixijs.com/8.x/guides/concepts/performance-tips)
- 保留提前构建、预稳定和 GPU 预热。准备预算按观测帧间隔调整，预热完成后停止轮询场景队列。录制从预稳定后的起点开始，分帧准备期间可取消。录制完成、取消和报错都释放视频轨道及临时数据。
- Compose 复用播放进度节点和当前片段引用，横向长片单按视口请求缩略图。完整 JPEG 资源继续可用，缺图回退的会话缓存有固定上限。

## 量化结果

浏览器矩阵以 720p 每 1/60 秒驱动一次 Director，完成每个片段的全部物理步骤和视觉状态更新，每 15 帧提交一次舞台绘制。表中是 315 个组合的分布，单位为毫秒。前后取同一轮压力测试期间的配对扫描。另一次独立基线的最慢单步均值为 1.037 ms，准备与全帧的绝对值会随并发负载变化。

## 1080p 循环压力

前后两版各真实播放 600 秒，七个重负载片段循环，走过全部七种转场。每版完成 74 次转场，处理约 9.6 万个 Chromium 动画帧。准备时间和帧间隔按 30 秒窗口统计，下表取窗口 P99 的中位数。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 每帧准备时间 P99 | 2.9 ms | 2.0 ms |
| 实际帧间隔 P99 | 8.4 ms | 8.2 ms |
| 最长观察到的帧间隔 | 39.7 ms | 43.0 ms |
| 强制 GC 后 JavaScript 堆范围 | 12.7–45.3 MiB | 12.2–44.3 MiB |
| 同一结束片段的 GC 后 JavaScript 堆 | 16.8 MiB | 16.3 MiB |

两版均完成约 600 秒的演出时钟推进。优化版活跃与预备合计最多两个场景，观察到的堆大小随片段变化，区间内无持续增长。采样期间浏览器还执行了验证负载和定期 GC。两版各有少量超过 33.3 ms 的间隔，优化版最长单帧仍有尖峰。控制台、WebGL、场景有限值检查均无错误。

## 回归与导出

- 315 个视觉组合全部跑完整段，位置、角度、上一物理位姿的采样指纹、步数及最大刚体数与基线一致。另抽取 945 个舞台帧，RGBA 像素 SHA-256 全部一致。
- 用相同场景验证每种画风的七种转场，包括地板实际打开。35 条转场路径的 105 个 WebGL 画面像素哈希全部一致。
- 真实 Chromium 验证了 Compose 增加、键盘换序、逐段转场覆盖、复制并还原分享 URL、暂停和跳段、全屏、390×844 的移动布局。63 段的 Compose 初次打开请求由 63 张图片降为 23 张。
- 线上复核发现 1280 像素宽的英文工具栏溢出。工具栏现可在任意宽度滚动，右侧操作保持可点击，桌面长片单也可滚至最后一个片段。
- 在暂停的纸艺场景强制丢失并恢复 WebGL 上下文，恢复后的全帧像素一致。
- 从真实导出对话框完成 720p 和 1080p H.264 下载，实测 1280×720 与 1920×1080，分别为 619 和 707 帧，时长均约 11.89 秒。原始数据包 DTS 严格递增，FFmpeg 全量解码通过。取消后验证恢复播放状态。重负载沙漏点击到录制轨道就绪为 720p 约 425 → 441 ms，1080p 约 472 → 431 ms。录制使用浏览器实时采样的可变帧率。[W3C Canvas 采集规范](https://w3c.github.io/mediacapture-fromelement/#html-canvas-element-media-capture-extensions)
- SAT 回归测试逐步比较常规和缓存版检测器的刚体状态及接触顺序。常规测试、类型检查和生产构建通过。

## 复现

在 Node 22 下使用 `npm ci`、`npm test` 和 `npm run build`。PowerShell 可按需运行全模板无头基准。

```powershell
$env:BENCHMARK = '1'
npm exec -- vitest run tests/zz-benchmark.test.ts --disableConsoleIntercept
```

浏览器的像素结果、实时时序和编码结果覆盖了本机硬件 Chromium。不同显卡、浏览器和移动设备的绝对耗时需单独测量。
